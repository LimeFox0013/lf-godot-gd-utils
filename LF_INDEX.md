# lf-godot-gd-utils — Index

The map of everything in lf-godot-gd-utils: what each class is for, and where its guide is.

## How to use this page

1. **Start with "Find it by task" below.** Each line is something you might want to do
   ("screen shake when something hits"), with the class that does it. Use your browser's
   search (Ctrl+F, or Cmd+F on macOS) for a word like *shake*, *save*, *loot* or *menu*.
2. **Click the class name.** It opens that module's page, which starts with *When to use
   it* and a *Step by step* guide you can follow in the Godot editor.
3. **Further down**, one table per group lists every class with its kind, its purpose and
   its main functions, for when you already know roughly what you want.

The *Kind* column says how you use a class (the main [README](README.md#how-lf-classes-work)
explains each kind): **static** means you call it on the class name; **RefCounted** (or
**Resource**) means you create one with `.new()`; a node type such as **Control** or
**Node3D** means you add it to a scene.

## For maintainers and AI assistants

- **Check this index before adding a helper, utility, component or system** to a project
  that uses LF. The `lf-utils-first` skill (`skills/lf-utils-first/`) walks an AI
  assistant through it.
- Every module lives in its own folder, `src/<group>/lf_<name>/`, holding the source, a
  `README.md` (step by step, full API, examples, notes) and, in the repository, a `tests/`
  folder of GUT tests (the release zip leaves the tests out). Every class is a global `class_name`: use it by name, never `preload` it.
- **Every module has the required parts**: a README and tests, and every class it declares
  (each `class_name`, and each public inner class as `Outer.Inner`) is named in the first
  cell of a row here. `tests/test_lf_index.gd` fails the suite on any module that falls
  short or any table whose rows don't line up.

Which modules are *stable* and which *experimental*, and how versions and deprecations
work: [`STABILITY.md`](STABILITY.md).

Groups, all under `src/`: `components/` (UI), `2D/`, `3D/`, `utils/` (everything that isn't drawn: core
helpers, input, timing and events, data, gameplay systems, files, network and system).

## Conventions

- **Style:** the [GDScript style guide](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/gdscript_styleguide.html).
  Files and folders are `lf_snake_case`, classes `LFPascalCase`, functions, variables,
  signals and parameters `snake_case` (private ones `_snake_case`), constants and enum
  members `CONSTANT_CASE`, enum names `PascalCase`. No trailing semicolons; `and`/`or`
  instead of `&&`/`||`; tabs for indentation. A file is named after its main class
  (`LFLayeredStats` → `lf_layered_stats.gd`). An inner class meant only for its outer
  class starts with `_`.
- **No magic values, no game concepts:** every meaningful number or string in library
  code is a named, documented constant (internal ones `_NAME`; public defaults
  `DEFAULT_<NAME>`, used in the signature). Library code, its doc comments and its tests
  know no game concepts (no "poison", "shop", "enemy"…); test fixtures use neutral names.
  Module READMEs may use concrete game examples to teach.
- **No warnings:** library code raises none of Godot's default GDScript warnings
  (`ci/check_install.sh` fails on any). Every public member has a `##` doc comment.
- **Static vs instance:** "static" classes are not meant to be instantiated. RefCounted and Resource
  classes are created with `.new(...)`. Node classes must be in the tree (`add_child`)
  before most of their API works.
- **Process-wide state:** everything is per instance except these static variables, shared
  by every scene for the life of the process:
  - `LFEventBus`: its one emitter. Reset it between tests or scene changes with
    `LFEventBus.clear()`.
  - `LFControl` / `LFControlOut`: the id registry. It needs no reset: a control leaves it
    when it leaves the tree or is freed.
  - `LFLogger.enable_print_logs` / `enable_print_warnings` / `enable_print_errors` and
    `LFSocket.log_traffic`, `LFThread.force_main_thread`: switches. A test that changes one
    restores it after.
  - `LFHelpTip.default_builder`: the panel builder for every tip without its own. Set it
    once at startup.
  - `LFSpriteAtlasFrames`: its frames and manifest cache, keyed by path and options, and
    its atlas image cache, keyed by texture and bounded by `max_cached_images`.
    `LFSpriteAtlasFrames.clear_cache()` empties both (after reimporting an atlas, or in tests).
  - `LFStatusEffectDef.shared`: one cached definition per id and policy, shared by every
    caller; treat the returned definition as read-only.
  - `LFProcess`: worker threads that outlived their grace period, joined later under a
    lock.
  - Caches and counters that never change an answer: `LFComponents` memoizes
    `components_dir()`; `LFFile` counts its temporary file names; `LFRandom` counts its
    unseeded sources; `LFFile` caches the system name; `LFAnimate` and `LFSpatialIndex` return shared read-only empties; `LFPasswordHash` keeps one `Crypto`; `LFOS` compiles one base64
    `RegEx`; `LFStatusEffects` keeps one shared empty id list it never writes;
    `LFRingSlots` builds its ring offsets once when the class loads and never writes them
    again, so `find_slot` writes no static state (the index and `Claims` it is given are
    still yours to guard).
  - Each module's private `_log` is a static `LFLogger`; it holds only a prefix.
- **Tests:** `tests/test_*.gd` beside each module, `extends GutTest`. Point GUT at the
  library folder with subdirectories included (in `.gutconfig.json` `dirs`). Run one test
  file by name, wherever lf-godot-gd-utils is installed:
  `godot --headless -s addons/gut/gut_cmdln.gd -gconfig=.gutconfig.json -gselect=<file>.gd -gexit`
- **Adding a module:** create `src/<group>/lf_<name>/` with the `.gd`, a `README.md` in the
  same template as its siblings (tagline, info table, When to use it, Step by step, API,
  Usage, Notes), and `tests/test_lf_<name>.gd`. Add a row to this file
  for every class it declares, with the class name (or `Outer.Inner` for a public inner
  class) in the row's first cell, and keep every table's rows at the header's cell count.
  Then run `godot --headless --import` from the project root so the `class_name`
  registers, and run the suite: `tests/test_lf_index.gd` must pass.
